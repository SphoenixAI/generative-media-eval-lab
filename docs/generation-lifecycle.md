# Private generation lifecycle

Plans, origins, selections and access attempts are local audit records, not judgments. Use `eval-pilot --root /tmp/TEST-ONLY-workspace` for TEST-ONLY fixtures; supply only human-authored declarations and generated test patterns in examples below.

`plan --file FILE` accepts JSON with optional `id` and required `family_id`, `arm`, `varied_factor`, `controlled_factors`, `prompt`, `model`, `model_version_string`, `settings`, `seed` (integer or null), positive integer `n_planned`, `intent_revision_ids` (an array of exact `ID@REV` strings, possibly empty), and `notes`. For legacy intent use `IntentSpec:ID@REV`; unprefixed intent IDs mean IntentSpecV2. Settings and controlled factors accept finite JSON, including nested and empty arrays. The application supplies `planned_at` and returns the immutable plan reference and artifact SHA-256. Plans with the same family ID share membership; different arms retain separate declarations. Settings, model version and seed do not verify execution or guarantee regeneration; no generator runs and no declared count is enforced.

`register DATASET CLIP FILE --label TEST-ONLY --plan PLAN_ID` records PLANNED origin and its exact plan pin. A sole listed intent binds automatically; multiple entries require `--intent ID@REV`; an empty list leaves intent evidence UNKNOWN. Without `--plan`, registration records FOUND and requires no model, seed, seal or intent. Registration records consideration, not retention. `bind-intent CLIP --intent ID@REV` binds existing intent later; it never authors or revises intent. `--prompt-only` is an explicit FOUND/v2 declaration. Origin and computed provenance are reported separately; quality remains UNKNOWN. PLANNED maps to the binding domain's GENERATED origin.

`selection DATASET --file FILE` accepts `id`, `candidates_considered` (ordered clip `ID@REV` strings), `rejected` (objects with `ref` as a clip `ID@REV` and nonblank `reason`), `random_draw` (nullable finite JSON metadata), and `kept` (clip `ID@REV` strings). Each candidate must belong to that exact dataset revision. Kept and rejected must partition the unique candidates. Reuse the selection ID to append a correction with its immediate predecessor's digest; rejected registrations remain stored. The program neither performs a random draw nor certifies sampling declarations. `intent_revision_ids`, `candidates_considered`, `rejected`, and `kept` must be JSON arrays; each rejection must contain exactly `ref` and `reason`. Malformed shapes return a structured error with quality UNKNOWN and do not admit a plan or selection record.

`open`, `open --at`, and `frames` verify source bytes then record the first access attempt before extraction or launch. Failure after logging preserves the attempt; missing/corrupt source bytes fail before logging. Attempts do not prove human attention. Repeated calls and byte-identical aliases reuse the first event, including after a backward clock reading. Future `play` must use the same helper; no player is added here. Viewing outside the CLI cannot be detected. Local timestamps cannot prove generation ordering. An initial bind without sufficient evidence degrades successfully; subsequent views or seals never silently refresh it, and explicit provenance promotions fail. Byte-identical aliases share the established binding origin, anchors and lineage. Missing legacy origin contexts remain absent; later aliases cannot supply their plans.

`show` and new private `snapshot` exports retain applicable lifecycle history and exact dependencies, including aliases. Earlier frozen exports stay fixed. These records include private prompts, notes and rejection reasons: do not publish private exports. Public/embed output exposes none of them. Separate file and record writes are not an atomic workflow; failures identify retained records and never delete history to roll back. The [provenance rules](intent-provenance.md) and [local seals](intent-seals.md) still apply.
