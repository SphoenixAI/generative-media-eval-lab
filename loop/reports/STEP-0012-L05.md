## Plan

### Goal and relevance to NORTH_STAR.md

Implement L05's separation between an intent-free technical observation and a human criterion assessment pinned to an exact intent revision. This supplies the technical and acceptability layers in `loop/NORTH_STAR.md` and lets a reviewer follow the same evidence into different declared creative contexts without rewriting what was observed. The intent-flip fixture demonstrates a software contract; it does not establish that intent explains human disagreement or validate any real-media judgment.

This is P2 planning only. This call changes only this Plan in `loop/reports/STEP-0012-L05.md`. Implementation, fixtures, tests and commands below are prospective work for P4.

### Acceptance criteria

Copied verbatim from `loop/backlog.toml:103`:

1. In the intent-flip fixture, identical observations under two sealed TEST-ONLY intents produce different assessments.
2. A TechnicalObservation that references intent is rejected.
3. UNKNOWN propagates.

Sharper criteria, retaining all three parent criteria and the record fields in `loop/backlog.toml:104`:

1. **TechnicalObservation.** Add an immutable artifact with `dimension`; `deviation` drawn from `NONE`, `MINOR`, `MATERIAL`, `SEVERE`, `CATASTROPHIC`, `UNKNOWN`; a finite, nonnegative, ordered time span within the referenced media duration; exact evidence pins; and `viewing_profile` (`FEED` or `STUDIO`). Include an exact media pin, authorship, and revision metadata for audit. It has no intent, criterion, binding, acceptability status or decision field. Evidence pins must resolve to `Evidence` for that same media, never to intent-bearing records; do not pin `PilotClip`, which can carry intent. Validate explicit and nested reference kinds and hashes. Reject unexpected intent fields at construction, JSON import and repository admission, including copies with injected fields before serialization could discard those fields. This is structural reference separation, not a claim that software can detect intent mentioned in arbitrary human prose.
2. **CriterionAssessment.** Add an immutable artifact with `criterion_id`, an exact `IntentSpecV2` reference and digest, status drawn from `SATISFIED`, `VIOLATED`, `NOT_APPLICABLE`, `UNKNOWN`, exact technical-observation pins, and nonblank human rationale. Retain media, author and revision metadata, plus an exact existing `IntentBinding` pin for provenance context. Check that binding, intent and media agree, the criterion exists in that exact intent revision, and cited observations belong to the same media and criterion dimension. Never resolve an omitted revision to latest. No automatic natural-language interpretation of acceptance, rejection or tolerance text determines status.
3. **Intent flip.** Use generated TEST-ONLY media and explicitly TEST-ONLY text. Seal two v2 intents through L03, list both exact revisions in a retained L04 plan, then register the clip after the plan. Bind each intent through consecutive revisions of the existing binding lineage, preserving its original media and registration pins; independently assert both bindings derive `SEALED`. Under one intent, a declared material sliding deviation is expected; under the other it violates the declared criterion. Submit explicit fixture assessments with literal expected statuses `SATISFIED` and `VIOLATED`, referencing exactly the same observation revision and digest, span, evidence and viewing profile. Assert the difference after repository reopen and private export. The fixture authors both statuses as test data; runtime records human judgments and does not manufacture them from an intent label. Also test that a later intent or observation revision cannot reinterpret either stored assessment.
4. **UNKNOWN.** An observation without evidence can be admitted only with deviation `UNKNOWN`; `NONE` requires supporting evidence. An assessment with no observations, or any cited observation whose deviation is `UNKNOWN`, can be admitted only as `UNKNOWN`, with a rationale explaining the gap. Known observations may still receive a human `UNKNOWN` assessment. Reject a submitted contradictory non-UNKNOWN status rather than silently changing the author's record. Test empty references, an all-UNKNOWN set, mixed known/UNKNOWN observations, and persistence/export round trips. `NOT_APPLICABLE` is an explicit human assertion with supporting known observations and rationale, never a substitute for missing evidence or an automatic consequence of criterion priority. Dangling references, wrong kinds, forged hashes and corrupt retained records are validation/integrity errors, not successful UNKNOWN submissions. If source media later becomes unavailable, preserve historical authored records and expose availability as UNKNOWN separately; do not rewrite the assessment or derive a current pass.
5. **Provenance boundary.** Reuse L02/L04 provenance unchanged. A `SATISFIED` assessment citing `MATERIAL`, `SEVERE` or `CATASTROPHIC` deviation requires a matching criterion/dimension declaration in that pinned intent's `expected_deviations` and a retained qualifying binding: `SEALED`, or `CONTEMPORANEOUS` with a visible contemporaneous-intent flag. Reject that attempted excuse with `RECONSTRUCTED` or `PROMPT_ONLY` provenance, without altering supplied records. Test these guards with fresh valid identities and exact context pins. These are structural admission rules enforcing I7; humans still decide whether evidence satisfies their criterion. No SHIP/HOLD or other terminal decision is produced.
6. **Append-only private workflow.** Add narrow human-form import commands `technical-observation CLIP --file FILE` and `criterion-assessment CLIP --file FILE`, retaining explicit exact pins and author declarations. Provide private `show` output and snapshot discovery for both new types, including records admitted directly through `Repository.put`, all applicable revision history and transitive pinned dependencies. Discover observations by exact included media; discover assessments by that media plus its retained exact binding/intent context, excluding unrelated datasets and same-ID/different-revision substitutions. Freeze earlier exports: appending a successor creates a new snapshot and never changes the old export. Corrections require a digest-pinned immediate predecessor and nonblank revision reason; preserve media identity and, within an assessment lineage, the criterion and intent/binding context. A different creative context uses a distinct assessment identity. Test reopen, revision gaps, wrong predecessor/hash, duplicate conflicts and direct SQL UPDATE/DELETE refusal.
7. **Compatibility and isolation.** Keep existing `Evidence`, `PilotSubmission`, `PilotClip`, v1 payloads/digests, the Phase 2 scoring engine, and accepted public/embed output unchanged. New artifacts carry their own authorship instead of expanding the accepted `PilotSubmission` schema. Test private export completeness and public/embed exclusion with explicit expected fields and sentinel private text. All exercised writes use temporary TEST-ONLY workspaces; none touch `pilot-local/`. Retain tool/version and media-hash evidence from existing ingestion and seals, and record the application version for new imports. Fixed-input record serialization and frozen-export replay must have deterministic tests; current clock values and fresh identifiers are not claimed deterministic.

### Method claims

Each external method claim relied on by this plan is listed separately. Primary sources were inspected during planning on 2026-10-09. Dependency contracts do not prove the proposed implementation correct; the planned tests must establish its behavior.

CLAIM L05-M01: Pydantic v2's extra="forbid" configuration raises a validation error when model validation receives fields not declared by the model.

Source: [Pydantic configuration: extra](https://pydantic.dev/docs/validation/latest/api/pydantic/config/#pydantic.config.ConfigDict.extra). Use strict admission plus explicit negative tests for intent-bearing payloads; do not treat the configuration alone as proof against unvalidated object copies.

CLAIM L05-M02: Pydantic 2.13.5's model_copy(update=...) copies the supplied update values without validating them.

Source: [Pydantic v2.13.5 BaseModel implementation](https://github.com/pydantic/pydantic/blob/v2.13.5/pydantic/main.py), `model_copy`; the installed version and method documentation were also inspected. Revalidate the new record types and nested pins, including copies with injected intent fields, before persistence.

CLAIM L05-M03: SQLite permits only one simultaneous write transaction, and BEGIN IMMEDIATE starts a write transaction immediately or can fail with SQLITE_BUSY if another connection already has an active write transaction.

Source: [SQLite transactions, sections 2.1 and 2.2](https://www.sqlite.org/lang_transaction.html). Reuse the repository writer boundary for state-dependent admission; separate workflow writes are not thereby atomic as a group.

CLAIM L05-M04: SQLite trigger execution of RAISE(ABORT, message) terminates the current query and returns SQLITE_CONSTRAINT with the supplied message.

Source: [SQLite CREATE TRIGGER, section 6](https://www.sqlite.org/lang_createtrigger.html). Retain and exercise the existing append-only guards; make no claim against database replacement or administrative removal of triggers.

CLAIM L05-M05: Python 3.12's hashlib provides sha256, whose hexdigest method returns a hexadecimal representation of the digest.

Source: [Python 3.12 hashlib](https://docs.python.org/3.12/library/hashlib.html). Reuse artifact digests and media checksums without a new hashing dependency or a claim that a hash authenticates a human judgment.

CLAIM L05-M06: RFC 8785 orders JSON object property names by UTF-16 code units and requires UTF-8 encoding of the resulting canonical serialization.

Source: [RFC 8785, sections 3.2.3 and 3.2.4](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2.3). Reuse L03's existing integer-only seal implementation for the TEST-ONLY intents without editing it; keep seal-source digests distinct from ordinary artifact digests.
