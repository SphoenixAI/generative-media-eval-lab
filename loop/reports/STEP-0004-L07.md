## Plan

### Goal and relevance to the north star

Implement L07, Hypothesis sets, as a small extension of the existing domain, repository and human authoring path. A human can record a revision-pinned `CompetingSet`, declare its `exclusive` and `exhaustive` flags, and record `compatible_with` or `refines` relations between named hypotheses. Exhaustive sets include the specified structural residual without manufacturing a substantive hypothesis or a confidence value.

`loop/NORTH_STAR.md:3-19` calls for evidence-linked, reproducible evaluation and a human-authored case that passes through competing hypotheses and a snapshot before later test and resolution stages. L07 supplies the competing-set record and preserves it in private snapshots; it does not run the flagship case, establish causal validity, or complete those later stages.

### Acceptance criteria

The complete acceptance list from L07 in `loop/backlog.toml:137`, copied verbatim:

- tests.

Sharper criteria below operationalize the item's notes and relevant invariants; they retain the criterion above.

1. A registered, persistable `CompetingSet` exposes `members`, `exclusive` and `exhaustive`. Named members reference exact existing `Hypothesis` revisions under one pinned intent revision. Reject empty named membership, duplicate hypothesis identities (including two revisions of the same hypothesis), wrong reference kinds, dangling references and cross-intent members. Accept a single named hypothesis; do not invent an alternative.
2. Exercise all four combinations of the two explicit boolean flags. An exhaustive set gains exactly one typed `RESIDUAL` member with the exact description `none of the listed causes`; a non-exhaustive set gains none. Revalidation, persistence and reload do not duplicate the residual. Reject malformed or duplicate supplied residuals and a residual supplied to a non-exhaustive set.
3. Represent the residual as a structural value embedded in the set's members, distinguishable from a named hypothesis reference. It has no confidence, evidence, observed problem, prediction, falsifier or supported status. Creating a set does not create or revise any `Hypothesis`. New synthetic authoring text is marked `TEST-ONLY`; the prescribed residual label is tested verbatim within those fixtures.
4. `compatible_with` and `refines` are accepted by the domain relation contract and existing human relation input. Both require hypothesis endpoints and the existing intent, author, purpose, scope and validity fields. Reject wrong endpoint kinds, self-relations, cross-intent endpoints and an `observed` epistemic status for either new kind. Preserve all existing relation-kind behavior. Treat compatibility as an unordered pair for conflict checks and refinement as the recorded subject-to-object direction; infer no additional edges, confidence changes or resolutions.
5. Reject a `compatible_with` relation between any two named members of a persisted exclusive set, in either endpoint order. Also reject admission of an exclusive set when that pair's compatible relation already exists. Test non-exclusive permission, unrelated hypotheses, overlapping sets, both insertion orders and revision admission. Perform the conflict check inside the repository write transaction, covering direct repository writes and objects copied without validation, not only CLI input. A file-backed concurrent set/relation admission test must show that conflicting records cannot both commit.
6. Define that conflict rule over exact pinned hypothesis references in retained exclusive-set revisions. A later member revision does not silently replace a pin or inherit membership; a later set revision does not erase an earlier constraint on its pinned pair. Test this conservative history rule explicitly. Set revisions pin their immediate predecessor, reject gaps and incorrect predecessor references, and preserve old canonical payloads and hashes. Replaying an identical revision remains idempotent; a conflicting rewrite is rejected.
7. Preserve each hypothesis's and relation's own confidence exactly, including `None` for unknown confidence and independently authored values that would exceed one if added. No set-level confidence, normalization, complement for the residual, averaging, probability arithmetic or automatic status update is introduced. Set creation and relation validation leave member artifacts unchanged, and missing evidence produces no pass or verdict.
8. Provide one narrow human authoring entry point, `eval-pilot competing-set CLIP --id ID --file FILE`, its blank draft form, and a corresponding `PilotWorkspace` method using the existing submission/session conventions. Resolve short member references once and store their exact revisions. Valid submissions appear in private `show` output, and snapshot/export includes the set, its predecessor chain and its pinned hypotheses through the submission root. A snapshot exported after later revisions still exports its original records and hashes. Exercise this flow only in temporary workspaces with generated media patterns and `TEST-ONLY` text.
9. With explicit fixture IDs and timestamps, repeated construction, JSON revalidation and repository reopen preserve set canonical bytes, hashes, member ordering and residual cardinality. Existing hypothesis/relation payloads receive no new serialized defaults. Existing protected artifacts remain byte-identical; public/embed output contains no competing-set payload or private member text. Add tests in a new file and retain every existing test unchanged.

### Method claims and implementation basis

Method claims: none

This step adopts the backlog's local vocabulary and validation rules. It relies on no external standard, statistical algorithm, calibrated probability interpretation, empirical effect size or external product capability. In particular, the words exclusive, exhaustive, compatible and refines describe human declarations and repository constraints; they do not claim that the causes have been scientifically established or completely enumerated.

The following checkable repository facts are the implementation basis, not external method claims:

- `Ref` stores `kind`, `id` and `revision`, and `Artifact.canonical` serializes model fields before `Artifact.digest` hashes those bytes (`src/eval_lab/domain.py:20-55`); adding default fields to existing artifacts would change their serialized representation.
- `Hypothesis` already stores optional per-claim confidence with `confidence_kind=subjective_unvalidated` (`src/eval_lab/domain.py:293-305`); L07 will preserve that representation.
- `RelationClaim` restricts predicates and endpoint kinds and rejects observed hypothesis claims, while `RelationInput` has a separate predicate allowlist (`src/eval_lab/domain.py:308-342`, `src/eval_lab/pilot.py:47-56`); both entry points must admit the two new kinds consistently.
- `Repository.put` revalidates serialized input, rejects conflicting existing revisions, and checks consecutive revisions inside its write transaction (`src/eval_lab/persistence.py:188-227`); the new exclusivity admission check must use that transaction's connection and read both relevant artifact kinds there.
- `PilotSubmission.human_record` currently rejects artifact kinds outside its four-kind allowlist (`src/eval_lab/pilot_domain.py:146-155`); accepting human set submissions requires a narrow addition to that list.
- `PilotWorkspace.snapshot` traverses references from the dataset, submissions, sessions and derivatives (`src/eval_lab/pilot.py:315-338`); a new set must be reachable from a submission rather than merely pointing toward an already reachable hypothesis.
- `serialize_case` constructs public/embed fields explicitly instead of exporting arbitrary domain artifacts (`src/eval_lab/presentation.py:53-74`); L07 will test that this boundary still excludes private sets and member text.
- The configured size gate counts added plus removed lines outside generated paths and limits them to 900 (`loop/config.toml:7-8,25`, `loop/gates.py:290-291`); this is a repository limit, not an external performance claim.

The additional choices in the sharper criteria, including the embedded residual, exact-reference conflict rule and lack of inferred relations, are proposed local contracts to prove with tests. No conformance claim or guarantee about untested database backends is made. The current checkout has the v1 hypothesis and intent contracts; L07 will not assume the availability of L02, L03 or L04, since its only backlog dependency is L00.
