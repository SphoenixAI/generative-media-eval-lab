### Acceptance criteria

Copied verbatim, in order, from L12-A1 in `loop/backlog.toml`:

1. The shared evidence boundary returns AVAILABLE(value), UNKNOWN(reason) for missing, null or unavailable evidence, or INTEGRITY_FAILURE(reason) for malformed, wrong-type, impossible, corrupt or integrity-invalid evidence. Do not introduce a new INVALID vocabulary.
2. Use the existing split mechanism if L12 cannot fit the configured 900 changed-line budget. Never remove, loosen or reduce tests to fit.

Sharper criteria for this child:

- Use exactly the three specified states. Only AVAILABLE carries a usable value; failure states carry stable, nonempty reasons and field/subject context. Do not use truthiness, coercion, defaults, empty collections, revision 1 or a latest revision to replace missing evidence. Zero, false and an empty collection can be AVAILABLE only when explicitly present and valid for the requested field contract.
- Direct raw input and the retained reader share the same field boundary. Inspect presence and original types before model construction. Missing/null/unavailable required data is UNKNOWN; present wrong types, unsupported vocabulary, impossible numeric values and integrity failures are INTEGRITY_FAILURE. A missing nested field and a malformed containing object have distinct diagnostics. An explicit unavailability token is recognized only where the field contract declares it.
- Resolve only explicitly requested Ref/Pin locations and exact `(kind, id, revision)` identities. Require an explicit positive integer revision; a missing/null component is UNKNOWN, while a present malformed component is INTEGRITY_FAILURE. A well-formed absent target is UNKNOWN. Verify row identity, payload identity, stored digest and supplied pin digest before allowing retained data to support AVAILABLE evidence. A missing/null required digest is UNKNOWN; a malformed or mismatched digest is INTEGRITY_FAILURE. Never reinterpret an arbitrary data mapping as a reference.
- Preserve accessible raw fields for diagnostics when retained data is damaged. Keep record integrity diagnostics separate from field diagnostics: a null field can remain UNKNOWN while a failed retained digest also reports INTEGRITY_FAILURE. No apparently valid field from an integrity-failed record may be delivered as usable AVAILABLE support. Unchecked raw diagnostic data must not be exposed as a checked value.
- Read an existing store without constructing a writable Repository, creating a workspace/schema, repairing records or reading media bytes. Missing/unavailable stores produce UNKNOWN; malformed stores, incompatible required structure and corrupt rows produce INTEGRITY_FAILURE. Reads within one reader session use one read transaction; every exit closes the connection. Test the application-level nonmutation and snapshot properties rather than claiming that a read-only connection implies absence of every filesystem side effect.
- Add focused negative and positive tests for every new primitive in this step. Include ordinary finite fractional evidence, valid non-motion dimensions, missing/null/invalid dimensions and decoded durations, malformed references, retained corruption and exact revision selection. These are primitive contracts; complete rule diagnostics and ready=false integration remain later children's obligations.

### Method claims

External claims are limited to the library behavior used by the proposed reader/parser. The following primary documentation was checked during planning; the build must still test the application behavior against the installed versions.

CLAIM L12-A1-M01: Python 3.12 sqlite3.connect with uri=True accepts a SQLite file URI with mode=ro to open a read-only database connection that rejects writes.
Source: [Python sqlite3 URI documentation](https://docs.python.org/3.12/library/sqlite3.html#how-to-work-with-sqlite-uris), corroborated by [SQLite URI modes](https://www.sqlite.org/uri.html).

CLAIM L12-A1-M02: After its first read establishes a snapshot, an explicit SQLite read transaction continues to see that snapshot rather than changes made by another connection until that transaction ends.
Source: [SQLite read transactions](https://www.sqlite.org/lang_transaction.html#read_transactions_versus_write_transactions).

CLAIM L12-A1-M03: Python 3.12 json decoding supplies each object's ordered name/value pairs to object_pairs_hook, permitting a caller to reject duplicate keys before constructing a dictionary.
Source: [Python JSON decoder hooks](https://docs.python.org/3.12/library/json.html#json.JSONDecoder).

CLAIM L12-A1-M04: Python 3.12 json decoding accepts NaN and infinity tokens by default, and parse_constant can reject those tokens while parse_float controls conversion of JSON fractional numbers.
Source: [Python JSON decoder hooks](https://docs.python.org/3.12/library/json.html#json.JSONDecoder). The planned boundary must additionally reject any nonfinite numeric result, including overflow, while retaining finite fractional numbers.

### Proposed implementation and focused verification

Add `src/eval_lab/lint_evidence.py` as an internal module using existing dependencies and the standard library. Keep its interface small: a tagged result, one field-availability entry point, strict primitive validation helpers, and a scoped raw exact reader. Validation helpers supply reasons to the shared boundary rather than creating competing state vocabularies. The field entry point receives explicit subject/path context and the applicable type/vocabulary/range contract. It must distinguish missing containers, null fields and malformed containers without filling defaults. An absent optional feature is a later checked applicability decision, not AVAILABLE(None) for an active prerequisite.

The reader will open the existing `pilot.sqlite` using a URI-safe path and read-only mode, begin a transaction and select by exact identity. Use raw JSON parsing with duplicate-key and nonfinite-number rejection while preserving finite ordinary fractional values. Validate the envelope and its identity before exposing checked field access. Match the existing artifact digest serialization on unnormalized payload data; do not reconstruct a model to regenerate omitted fields or normalize a damaged record into a passing hash. Check supplied pin identity/hash, and use the separate existing freeze digest for applicable frozen TestPlan payloads. Keep raw diagnostic inspection available without promoting an integrity-failed record to usable evidence. Do not perform automatic graph traversal, collection-completeness reasoning or rule evaluation in this child.
