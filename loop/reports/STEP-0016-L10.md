## Plan

### Goal and relevance to the north star

Implement L10, Resolution events: a private `eval-pilot resolve` command that consumes an explicitly frozen test plan, a human-declared outcome and qualifying evidence, then appends reproducible hypothesis-status events. This supplies the result-to-resolution stage in `loop/NORTH_STAR.md`'s flagship sequence. A reviewer must be able to trace each status to the exact plan, named hypothesis revision, declared outcome and evidence used. This step builds infrastructure with TEST-ONLY fixtures; it does not resolve the three real human cases or establish their methodological validity.

### Acceptance criteria

Copied verbatim from L10 in `loop/backlog.toml`:

> elimination tests, plus rejection of unfrozen plans, non-TEST_RESULT evidence and insufficient samples.

Sharper criteria implementing the item's notes:

1. `resolve` requires an exact TestPlan revision/digest pin, a retained explicit freeze with valid dependencies, an outcome contained in that plan's `outcome_categories`, and nonempty evidence. A draft, altered freeze, absent dependency, invalid pin or undeclared outcome cannot produce an elimination event. Missing necessary evidence remains UNKNOWN; integrity failures remain distinguishable from missing evidence.
2. For a determinate result, every named member of the plan's pinned CompetingSet receives RETAINED exactly when its declared predictions contain the supplied outcome, and ELIMINATED otherwise. Identical predictions retain all compatible members; partial overlap does not force a single winner. The result never edits `Hypothesis.status`, confidence, observations, intent, relations, assessments, policies or verdicts.
3. An existing structural RESIDUAL is always RETAINED, including when named members survive. It is the only survivor when no named member predicted the declared outcome. A non-exhaustive set remains non-exhaustive: do not insert a residual into its membership; report an unpredicted outcome with no named survivors and the absence of a residual explicitly.
4. Evidence eligibility is recomputed for every submitted evidence/named-hypothesis pair against the exact target plan and arm. DISCOVERY, SUPPORTING, UNKNOWN and integrity failures cannot satisfy TEST_RESULT. A qualifying link to another plan or revision cannot authorize this resolution, even if the general evidence-role query would choose it first.
5. Enforce the frozen sample design per arm, never through a pooled count. For `n_per_arm`, each covered arm must have at least that many distinct qualifying sample units. Every generation-plan arm is sample-gated; when a sample design is declared, enforce it for all declared arms. Without a sample design, require qualifying evidence for every arm and make no stochastic-sufficiency claim. Reject omitted arms, duplicate submissions and attempts to inflate counts through multiple frames, evidence revisions, link aliases or repeated registrations of the same source.
6. For a frozen textual `stopping_rule`, require an explicit human declaration that the rule was met, attributed to the submitting author, naming the exact rule/plan and affected arms, referencing qualifying samples and giving a nonblank reason. Missing, false, mismatched or reasonless declarations are insufficient. The program validates this declaration and its evidence references; it does not interpret arbitrary prose or independently certify that the human rule was satisfied. A stopping declaration cannot bypass a fixed `n_per_arm` design or TEST_RESULT eligibility.
7. Support an explicit human request for INDETERMINATE with a nonblank reason. It leaves named hypotheses unresolved, retains any residual and records the reason. It is not a fallback for invalid inputs or insufficient samples: the same frozen-plan, category, evidence and sample prerequisites apply.
8. Store one immutable event containing the complete member-status tuple, human input and provenance. Corrections append the next same-ID revision with the immediate predecessor's exact pin and a reason; they never overwrite or delete prior events. Application-owned statuses, role results, counts, timestamps, rule/tool versions and input hashes cannot be supplied as authoritative human fields.
9. Validate both CLI and direct repository admission, including forged model copies, within the repository's writer transaction. Failed admission appends no event and leaves authored artifacts unchanged. Retain the exact consulted context and dependency pins so later plan, hypothesis or evidence-link revisions cannot rewrite a historical result.
10. Private `show`, runtime schema output and new dataset snapshots expose the event and its required history/dependency closure, including cross-clip arm evidence. Earlier snapshot exports remain identical; public/embed serializers omit resolution inputs, private reasons, event records and unpublished dependencies.
11. Tests prove stable classification, member ordering, counted sample identities and replay from the same pinned inputs, including after reopening storage and after later context corrections. Record the resolution rule version, installed package version and input/artifact hashes. A fresh invocation's timestamp is not claimed to be deterministic.

### Method claims

Method claims: none

This plan introduces repository-defined admission and prediction-membership rules, not an external scientific method, calibrated sample-size recommendation or claim about another product. The following are local contracts to verify in code and tests:

- `src/eval_lab/test_plans.py` retains explicit freeze revisions, exact dependency checks, outcome categories, predictions and mutually exclusive fixed-count/textual-stopping sample designs; resolution will reuse those contracts.
- `src/eval_lab/evidence_roles.py` computes pair-specific roles and currently considers links across plans; resolution must restrict the candidate context to the target plan and arm before accepting a role.
- `src/eval_lab/domain.py` supplies exact named CompetingSet members and a structural residual only for exhaustive sets; resolution will preserve that distinction.
- `src/eval_lab/persistence.py` supplies immutable artifact revisions and a writer-transaction admission path; the new event type must join that path rather than rely on CLI validation alone.
- For generated-clip samples, use retained source-content identity to collapse repeated registrations and multiple frame/evidence records. For instrument-run samples, use the exact retained run lineage, collapsing its revisions and link aliases; require its checked source/output association. Count these as declared sample units, without asserting statistical independence. Pin the chosen units and reject reuse across arms that would inflate their counts.
- The selected outcome and any interpretation of `decision_rule` remain human declarations, with a retained rationale linking the outcome to that rule when a sample design is present. No majority vote, averaging, likelihood, confidence arithmetic or causal-truth inference is introduced.
- Existing digest helpers are reused as local integrity contracts. This step makes no new standards-conformance, authenticated-chronology, instrument-validity or statistical-power claim.
