## Plan

### Goal and relevance to NORTH_STAR.md

Implement L10, Resolution events: private `eval-pilot resolve` infrastructure that consumes a human-declared outcome, an explicitly frozen test plan and qualifying evidence, and appends reproducible hypothesis-status events. This supplies the result-to-resolution stage of the flagship sequence in `loop/NORTH_STAR.md`. Each status must be traceable to exact retained inputs and dependencies. Build validation uses TEST-ONLY fixtures; it does not resolve real cases or establish empirical validity.

### Acceptance criteria

Copied verbatim from L10 in `loop/backlog.toml`:

> elimination tests, plus rejection of unfrozen plans, non-TEST_RESULT evidence and insufficient samples.

Sharper criteria implementing the item's notes and addressing prior findings:

1. Require an exact TestPlan revision/digest pin, a retained explicit freeze and valid dependency closure, an outcome in that plan's `outcome_categories`, and nonempty evidence. Reject drafts, invalid pins, missing dependencies and undeclared outcomes without appending an event. Missing evidence remains UNKNOWN; integrity failure is distinguishable from absence.
2. Verify the retained frozen-plan JSON before model normalization, both during resolution preparation and inside transactional admission. Apply the existing `freeze_digest` operation to the raw parsed object before model defaults can be restored, then validate the typed artifact, stored artifact digest, dependency pins and explicit-freeze transition. Route both reads through a shared retained-row check in `src/eval_lab/persistence.py`; a preflight-only verifier or reconstructed model dump does not satisfy this criterion. Delete each default-valued field covered by `tests/test_test_plan_workflow.py::test_retained_default_deletion_is_integrity_failure`, including `schema_version` and `tool_version`, while preserving stored hashes: fresh resolution attempts must reject with a frozen-digest integrity error and append nothing. Cover damage before preparation and damage after preparation that is first encountered by the transaction's getter. Also retain rejection coverage for changed content, bad hashes and missing dependencies.
3. For a determinate result, each named member of the pinned CompetingSet is RETAINED exactly when its predictions contain the declared outcome, and ELIMINATED otherwise. Identical and overlapping predictions can retain multiple named hypotheses. An existing structural RESIDUAL is always RETAINED and is the only survivor for an unpredicted outcome. Do not invent a residual for a non-exhaustive set; explicitly report an unpredicted outcome and no survivors when none exists. Never edit hypothesis status, confidence or other authored records.
4. Recompute TEST_RESULT eligibility for every submitted evidence/named-hypothesis pair in the exact target plan and arm context. DISCOVERY, SUPPORTING, UNKNOWN and INTEGRITY_FAILURE cannot authorize a resolution. Links to another plan or revision cannot qualify, even if the general evidence-role query would select them first. Preserve the exact consulted context and dependency pins for replay.
5. Enforce a declared `n_per_arm` independently for every declared arm; generation-plan arms are always sample-gated. Without a sample design, require qualifying evidence for each arm and make no stochastic-sufficiency claim. Count distinct qualifying sample units, not frames or records: collapse repeated registrations of identical source content and evidence/link aliases; collapse revisions of the same declared instrument-run lineage. Reject duplicate submissions, omitted arms, reuse across arms and attempts to inflate counts. Use literal one-below, exact and above-count test cases. A sufficient pooled total cannot excuse an underfilled arm.
6. For a frozen textual `stopping_rule`, require an explicit human declaration that the exact rule was met, attributed to the submitting author, naming the pinned plan and affected arms, citing qualifying samples and giving a nonblank reason. Missing, false, mismatched and reasonless declarations fail admission. Validate the declaration and references; do not interpret arbitrary rule prose or certify its truth. A stopping declaration cannot bypass a fixed-count design or TEST_RESULT eligibility. When sample design is present, retain the human rationale linking the declared outcome to its frozen `decision_rule`.
7. Permit an explicit human request for INDETERMINATE only with a nonblank reason. Named members remain unresolved and any residual remains RETAINED. The same frozen-plan, category, evidence and sampling prerequisites apply; indeterminacy is not an escape from insufficient or invalid inputs.
8. Append an immutable event containing the member-status tuple, human input, exact context/dependency pins, sample identities, rule/tool versions and hashes. Corrections use the next same-ID revision, the immediate predecessor's exact pin and a nonblank reason. Old events and earlier snapshot exports remain unchanged. Reject caller authority over computed statuses, roles, counts, versions, hashes and timestamps through JSON input and direct repository admission, including model copies.
9. Enforce application ownership of `created_at` at admission, using an application-issued receipt bound to the prepared event and checked against issuance state outside caller-editable event fields. Do not copy a supplied timestamp into an expected event and compare only other derived fields. Preparing an otherwise valid, fresh-ID event and changing only `created_at` to another valid timezone-aware instant must raise a specific application-owned timestamp error and append nothing. Cover initial and successor events, and retain a positive admission case with an unaltered issued timestamp. This is local issuance integrity, not authenticated chronology.
10. Revalidate inputs and derived fields inside the repository writer transaction using its retained-record getter. Preparation is not admission authority. Tests must isolate corruption or context changes first seen at this boundary, verify the specific rejection, and verify no event or reference rows were appended. Reject forged nested pins and stale/incorrect predecessors without changing authored artifacts.
11. Private `show`, runtime schema output and new dataset snapshots expose applicable events, predecessor histories and full pinned dependency closure, including cross-clip arm evidence. Replay and reopening storage preserve statuses, member ordering, sample identities and hashes despite later context revisions. Fresh invocation timestamps are excluded from the determinism claim. Record actual tool versions and hashes during build validation.
12. Public and embed serializers omit resolution events, inputs, private reasons and unpublished dependencies in both blind and revealed states. Create TEST-ONLY resolutions associated with the exact intent or media of the actual serialized case, assert that association and private-record presence as positive preconditions, and use distinctive event/input/reason markers. Make a pairwise submission to reach and assert the revealed state. All four mode/state combinations must detect a deliberate associated-resolution disclosure mutation.

### Method claims

Method claims: none

There are no external standards-conformance, statistical, algorithm-performance or product claims requiring verification in this work. The method is the repository's specified prediction-membership and admission policy. The following local contracts are checkable against repository code and the planned tests:

- `src/eval_lab/test_plans.py` defines explicit freeze transitions, exact dependencies, outcome predictions and mutually exclusive fixed-count or textual-stopping sample designs.
- `src/eval_lab/test_plans.py::verify` checks a retained TestPlan's raw parsed payload before typed reconstruction; current `Repository.get` and the transactional getter in `src/eval_lab/persistence.py` reconstruct first, so resolution needs the raw check on both paths.
- `src/eval_lab/evidence_roles.py::compute` derives pair-specific roles and searches links across plans; resolution must supply a context scoped to the exact plan and arm, using the existing role rules.
- `src/eval_lab/domain.py` distinguishes named CompetingSet members from the structural residual of an exhaustive set; status derivation must preserve that membership.
- Source-content identity is the declared generated-clip counting unit, and retained run lineage is the declared instrument-run counting unit; these rules prevent record duplication from increasing counts and do not establish statistical independence.
- The outcome, decision-rule rationale, stopping declaration and indeterminate reason are human inputs; the application computes prediction compatibility and admission sufficiency without deriving those human inputs.
- Existing digest helpers are reused as local integrity contracts; this step adds no canonicalization-standard implementation, cryptographic-authenticity guarantee, statistical-power recommendation, probability arithmetic or causal-truth inference.
- Determinism means identical pinned inputs and context yield identical statuses, ordered dependencies and counted units; it does not mean separate invocations share a timestamp.
