### Acceptance criteria copied verbatim from loop/backlog.toml

- Every derivation case is tested.
- A revision cannot borrow an earlier revision's seal.
- A revision without a reason is rejected.
- No edit can raise a record's provenance.

Additional acceptance criteria that sharpen those requirements:

- V2 validates `use_context` with `surface`, `audience` and `viewing_profile` (`FEED` or `STUDIO`); `criteria[]` with `id`, `dimension`, `priority` (`MUST`, `SHOULD`, `COULD` or `WONT`), `acceptance`, `rejection` and `tolerance`; and `expected_deviations[]` with `dimension`, `description` and `criterion_id`. Criterion IDs are unique within a revision, and each deviation references a criterion in that exact revision with the same dimension. Multiple criteria may concern one dimension. Required text rejects blank or whitespace-only values. Tolerance is human-authored text, not an inferred numeric threshold. No dimension receives a `SENSITIVE` or `INVARIANT` label.
- Every newly authored v2 snapshot, including revision 1, requires `revision_reason` from `SERENDIPITY`, `CLARIFICATION`, `CORRECTION` or `SCOPE_CHANGE`. A subsequent revision pins its immediate predecessor of the same identity; missing, cross-kind, cross-ID, skipped or stale predecessors are rejected. Legacy loading does not fabricate a reason or new criteria.
- The classification order is exactly the backlog's: `SEALED` when the exact revision's seal precedes a matching plan and that plan precedes this clip's registration; otherwise `CONTEMPORANEOUS` when the exact revision was sealed strictly before this clip's first logged view; otherwise `RECONSTRUCTED`. Strict inequalities exclude equality. Missing evidence cannot satisfy an ordering predicate; an absent first-view record does not mean an infinitely late view. A missing first view does not invalidate an independently satisfied `SEALED` predicate.
- A plan must list the exact revision, and the seal evidence must match that revision and its content digest. An earlier revision's seal or a plan listing only an earlier revision never qualifies. Insufficient or nonqualifying ordering evidence falls through to the supported class; malformed inputs, invalid reference kinds or demonstrable digest tampering are rejected rather than silently treated as authentic evidence.
- Human input cannot assign `SEALED`, `CONTEMPORANEOUS` or `RECONSTRUCTED`. The only declaration is `PROMPT_ONLY`, and it is accepted only for a `FOUND` clip. A `FOUND` clip without that declaration uses the normal evidence rules; it cannot use an unrelated plan to obtain `SEALED`.
- Provenance belongs to an immutable clip/intent binding snapshot, not to an editable label on the intent. Existing snapshots cannot be overwritten or promoted by changed times, plan membership, copied model data, a new seal, or an intent edit. Any permitted successor pins its predecessor and preserves or lowers the previous provenance ceiling. A new intent revision does not rewrite an earlier binding; a genuinely new clip registration is a distinct record with its own derivation.
- Pilot 0 intents are exposed as `RECONSTRUCTED` through a read-only compatibility view. Their original references, content, canonical serialization and digests remain unchanged. They are not silently converted into authored v2 records, and no missing context, criterion, reason or seal is invented.
- Classification does not create an assessment, excuse a deviation or produce a verdict. Missing assessment evidence remains `UNKNOWN`. Documentation explains the evidence and limits of each class, including the inability of local timestamps to establish generation order without an external witness.

### Method claims and repository contracts

External factual claims for deterministic extraction and independent fact-checking:

CLAIM L02-M01: Pydantic v2's BaseModel.model_copy(update=...) does not validate the supplied update values before returning the copied model.

Source: [Pydantic v2 BaseModel.model_copy documentation](https://docs.pydantic.dev/2.12/api/base_model/#pydantic.main.BaseModel.model_copy), checked during planning on 2026-10-08; the installed implementation agrees. Consequence: the build must test revalidation at the persistence boundary, including invalid copied objects, rather than relying on frozen model assignment checks alone.

CLAIM L02-M02: RFC 3161 time-stamping supplies evidence that a datum existed before a particular time and requires a trustworthy time source; it does not inspect the meaning of the time-stamped datum.

Source: [RFC 3161, sections 1 and 2.1](https://www.rfc-editor.org/rfc/rfc3161.html), checked during planning on 2026-10-08. This is an evidentiary boundary, not a proposal to implement that protocol.

CLAIM L02-M03: A locally recorded seal-plan-registration timestamp sequence alone cannot prove that the clip was actually generated after the intent was sealed.

This is an inference from the distinction between logging an event and independently witnessing that event, consistent with [RFC 3161's proof-of-existence scope](https://www.rfc-editor.org/rfc/rfc3161.html#section-1), and an explicit limitation required by L02. A clip generated earlier and registered later is a counterexample to equating registration order with generation order. Even a witness to an intent's existence would not, by itself, witness the clip's generation event.

The remaining method statements are local contracts or proposed implementation choices, not claims of external validation:

- `loop/backlog.toml` L02 defines the provenance algorithm and enumerations; the words `MUST`, `SHOULD`, `COULD` and `WONT` are this repository's criterion priorities, without claiming compliance with a requirements standard.
- `src/eval_lab/domain.py:IntentSpec` is the existing v1 type with legacy `Criterion` values; `Artifact.canonical` serializes model fields, and `Artifact.digest` hashes that serialization. Adding default fields to that type could change stored snapshots' digests, so v2 will be additive rather than a rewrite of v1 payloads.
- `src/eval_lab/pilot.py:PilotWorkspace.intent` currently records the free-text revision reason in a submission, not in the v1 intent. Existing v1 tests exercise that interface. The new mandatory enum belongs to the explicit v2 authoring contract; legacy records are readable as reconstructed evidence, not accepted as reasonless v2 revisions.
- `src/eval_lab/persistence.py:Repository.put` revalidates serialized input, rejects conflicting content at an existing identity, and requires consecutive revisions. New v2 link and predecessor checks must run on this persistence path as well as at model construction; a helper-only check would be insufficient.
- Derivation will use explicit, timezone-aware event facts normalized to UTC, exact revision references and pinned digests. It will not substitute the current clock, an intent's generic `created_at`, a clip's latest edit time, or the latest revision for missing event evidence.
- The algorithm is a local evidence classification policy, not a calibrated confidence scale or proof of human authorship, intent quality, actual generation chronology or acceptability. `PROMPT_ONLY` is a declaration with limited evidentiary scope, not an ordinal score to average with other classes.
- Determinism is an acceptance target to be demonstrated with fixed inputs and replay tests, not an established result of this planning call. No new canonicalization or cryptographic security property is claimed; L03 owns canonicalization and seal verification.
- The frozen step configuration sets a 900-line limit, counting additions plus removals outside generated paths. The size estimates below are planning budgets, not measured implementation counts.
