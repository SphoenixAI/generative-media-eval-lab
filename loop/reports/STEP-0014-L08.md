### Acceptance criteria

Copied verbatim from L08's acceptance array in `loop/backlog.toml:154`:

> one fixture per class, an identical-prediction pair, a single-hypothesis plan, rejection of empty predictions, freeze and digest checks, and the sample-design rule.

The following sharpen that criterion and preserve every rule in L08's notes:

1. **Complete private contract.** TestPlan carries `competing_set` as an exact reference and digest pin, `arms[]` with unique nonblank `id`, `description` and `generation_plan_ref` or null, optional `sample_design`, `measurement` with kind HUMAN or INSTRUMENT and a nonblank protocol, unique nonblank `outcome_categories[]`, `predictions`, `frozen_at` and `frozen_digest`. Include identity, revision, immediate predecessor pin, author declaration and application-recorded tool version. Require at least one arm and outcome category. Generation references resolve to retained GenerationPlan records; wrong-kind, missing and mismatched pins are rejected. An instrument is a declaration only and is never invoked.
2. **Prediction coverage.** Predictions map every named hypothesis ID in the selected CompetingSet revision to a nonempty set of declared outcome IDs. Missing hypotheses, unknown hypothesis keys, residual predictions, unknown outcome IDs and empty predictions are rejected. Outcome order inside a prediction does not alter the class. A declaration cannot silently gain a new hypothesis because a newer set or hypothesis revision exists. Preserve the named members' exact revisions through the competing-set pin; do not copy their confidence values into an aggregate.
3. **Ordered diagnosticity.** For each declared outcome `o`, compute `compatible(o)` from named hypotheses whose predictions include `o`. First return NON_DIAGNOSTIC when every named hypothesis predicts the same outcome set, including the single-hypothesis case. Otherwise return DECISIVE when every `compatible(o)` has at most one member. Otherwise return PARTIALLY_DIAGNOSTIC. Report every outcome with no compatible named hypothesis as UNPREDICTED, separately from the class. If present, exclude the residual and report exactly `not testable by this plan`. The fewer-than-two rule includes zero at the classifier boundary, but an empty CompetingSet remains inadmissible under L07.
4. **Literal class fixtures.** Use TEST-ONLY named hypotheses A and B and outcomes X, Y and Z: A predicts X and B predicts X for NON_DIAGNOSTIC; A predicts X and B predicts Y for DECISIVE; A predicts X,Y and B predicts Y for PARTIALLY_DIAGNOSTIC. Z is UNPREDICTED in each fixture. A single hypothesis predicting X is NON_DIAGNOSTIC even though all compatible sets have at most one member. In a three-hypothesis case, A predicts X, B predicts X and C predicts Y: the expected class is PARTIALLY_DIAGNOSTIC, proving that one identical pair does not imply all hypotheses agree. Repeat the relevant cases with a residual and reordered prediction lists. All fixture prose is marked TEST-ONLY.
5. **Sample design.** Require `sample_design` whenever any arm references a generation plan, including mixed null/referenced arms. When supplied, require exactly one of a strictly positive integer `n_per_arm` or a nonblank `stopping_rule`, together with a nonblank `decision_rule`. Reject booleans, nonpositive counts, both alternatives, neither alternative and a missing decision rule. Null-only arms may omit sample design. Record the human rule without executing sampling, selecting a sample size or judging statistical adequacy.
6. **Explicit freeze and immutable revisions.** Importing, inspecting or classifying a draft leaves both freeze fields null. A dedicated `freeze-test-plan ID@REV` command revalidates the current draft and its exact dependency pins, then appends a frozen successor with the immediate predecessor's reference and artifact digest; it never updates the draft in place. Preserve all authored plan content and the selected set revision. Reject a stale draft target and attempts to freeze an already frozen version. Ordinary authoring imports cannot supply application-owned freeze metadata. Later edits append a new unfrozen version with a checked predecessor and require another explicit freeze. Retain all prior drafts and frozen versions.
7. **Defined freeze digest.** Compute `frozen_digest` as SHA-256 over L03's JCS canonicalization of the complete frozen TestPlan JSON representation with only `frozen_digest` omitted. Include identity, revision, predecessor, set and generation pins, all authored fields, freeze timestamp, tool version and the declared canonicalization/profile metadata. Use the existing `safe-integer-tokens-v1` profile; do not hash referenced hypothesis confidence values or entire generation settings into this payload. Referenced artifacts retain their existing artifact hashes. The freeze digest and repository artifact digest are distinct and must not be substituted for each other.
8. **Verification and failure evidence.** Verify a retained exact frozen revision and, when supplied, a candidate frozen file against that retained revision. Recompute its freeze digest, check its stored artifact integrity and exact dependency digests, and reject tampering with every covered field, including timestamp, predecessor, set revision, arm, measurement, outcomes and predictions. A candidate with a recomputed forged digest still fails comparison to the retained revision. Key order and insignificant JSON whitespace leave the JCS digest unchanged; array order remains covered. Include a literal canonical byte string and independently specified expected digest. Missing workspace, record or dependency yields UNKNOWN; corruption or mismatch yields INTEGRITY_FAILURE; both return nonzero. A draft is explicitly NOT_FROZEN, never verified by default. Verification is read-only and does not create a missing workspace, repair data or freeze a plan.
9. **Bounded integration.** Provide private author/import, freeze and verify CLI commands, expose these records in private inspection and include relevant plan histories and pinned dependencies in future private snapshots. Earlier exports remain byte-for-byte unchanged, unrelated plans stay out of a dataset's snapshot, and public/embed serializers emit none of the new private prose or records. No hypothesis status, confidence, observation, assessment, verdict or policy is changed by these operations.
