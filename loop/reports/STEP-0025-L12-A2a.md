Shared preparation infrastructure declares and checks traversal, exact Ref/Pin dependencies, explicit collection completeness, raw record identity and integrity, and scoped media/intent correspondence through the existing evidence boundary. ### Owned design and sharper acceptance criteria

1. **Explicit declarations and checked traversal.** Add a small shared declaration mechanism for scalar fields, containers/elements, exact Ref/Pin edges, scoped collections and correspondence checks. Each declaration identifies its group, source kind/path, raw contract, target kind where applicable, and declared dependencies. Keep ordinary mapping keys such as `kind`, `id` and `revision` as data unless their location is explicitly declared as a reference. Traverse exact identities with a visited set; revisiting a valid record cannot skip a different path, pin or scope obligation. Reject invalid declaration dependencies rather than silently dropping them. Do not construct authoring models, inject defaults or synthesize residuals.

2. **One evidence boundary.** Reuse `field`, `Contract`, `EvidenceResult` and `RawRecord.field` in `src/eval_lab/lint_evidence.py`. All consumed containers, leaves, reference components, collection metadata and correspondence operands must pass through this boundary. Only AVAILABLE can supply checked support. Missing/null/unavailable inputs remain UNKNOWN; malformed, wrong-type, inconsistent or corrupt inputs remain INTEGRITY_FAILURE. Preserve explicit subject, state, path and reason, including record-level failure alongside a missing field. Do not introduce INVALID or coerce unavailable values into false, zero, an empty collection or an inactive branch.

3. **Exact raw dependencies and integrity.** Reuse the retained exact reader and factor only the small verification seam needed to give direct raw records equivalent identity and digest checks. Direct TEST-ONLY records must provide an explicit envelope and raw payload, not a typed object whose defaults conceal omissions. Require explicit kind, id and positive revision; check declared target kind, row/envelope-to-payload identity, kind-specific schema version, stored digest and supplied pin before field support. Never fall back to a latest revision. Preserve existing retained JSON/frozen-plan integrity behavior. Add narrow version support for the existing v2 kinds without allowing version 2 on version-1 kinds or arbitrary versions. This is compatibility with the current models, not a schema migration or digest-algorithm change.

4. **Explicit collection completeness.** Declare the collection's source, allowed kind, scope and membership before using it. The retained adapter must enumerate raw exact identities within the existing reader session, verify every member, and report enumeration failure; do not accept caller-provided `complete=true` as evidence. The direct adapter uses an explicit TEST-ONLY record universe and scope inventory, then checks enumeration and membership against that universe. Missing inventory, missing declared members and unavailable enumeration cannot become an empty collection. Duplicate/conflicting identities and malformed membership are integrity failures. A successfully enumerated empty collection is usable only for that declared scope. Direct scope completeness does not attest that a caller supplied an entire real case; L12-C owns real case-query orchestration.

5. **Scoped media/intent correspondence.** Provide shared checks that compare independently checked exact media and intent references/pins against the requested scope and declared dependency endpoints. Same id with a different revision or wrong kind is not correspondence; pin failure cannot be hidden by matching references. Require only the scope operands declared for that group: technical-only preparation does not acquire an intent dependency. A legitimately media-only group is an explicit contract, not a fallback selected by missing intent. Do not equate different media identities merely because a timestamp or other incidental field matches. FirstView/registration/content-hash and seal/origin/plan semantics remain A2c's responsibility; attachment selection remains A2b's responsibility.

6. **Checked output and coverage accounting.** Expose checked scalar values and checked container membership/indices with their subjects and paths, never unchecked descendant payloads or `diagnostic_raw` as support. A consumer access must have a declaration and AVAILABLE evidence; missing declarations and unconsumed active declarations must be detectable. An independent, test-authored shared inventory must equal the implemented shared inventory, not merely be a subset of it or a deduplicated uniqueness check. Record actual boundary consumption for every active shared prerequisite. Successful shared preparation must identify its limited group/scope and cannot return a usable all-rule context, `ready=true`, PASS, COMPLETE or SHIP. No all-rule completion API is introduced in this child. Later groups must extend declarations and tests before A2d can establish the conjunction.

- **G08, preservation and reproducibility:** `test_shared_preparation_preserves_inputs` checks raw payloads, digest identities and disposable retained store bytes before/after success and failure. `test_shared_diagnostics_repeat_and_order` checks identical diagnostics and checked values for repeated preparation and reordered input enumeration.
