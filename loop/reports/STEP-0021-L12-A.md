### Goal and relevance to NORTH_STAR.md

Implement L12-A's private, read-only evidence prerequisite layer: explicit declarations for every lint rule, one shared availability boundary, exact-reference raw retained access, and exhaustive parameterized contract tests. The later evaluator must consume this layer before it can report a clean rule result. This supports the lint-to-snapshot stage in `loop/NORTH_STAR.md`: a reviewer can distinguish structurally checkable evidence from missing or corrupt context while auditing the first human-authored cases. Availability does not establish the truth of an observation, the correctness of a hypothesis, or acceptability of a clip.

### Implementation design and prerequisite inventory

Add one small internal module, `src/eval_lab/lint_evidence.py`. It owns the declaration registry, the shared boundary, raw evidence access and branch-context preparation. Separate access/validation from future rule predicates. Each declaration has a stable prerequisite ID, rule ID, source/path, expected shape or vocabulary, applicability condition, reference/dependency requirements and validation checks. Shared declaration groups may expand into several rules, but the expanded inventory must be inspectable and tested per rule and field. Do not make the module a general validation framework or duplicate the domain evaluators.

Use precisely AVAILABLE(value), UNKNOWN(reason) and INTEGRITY_FAILURE(reason). Validate original field presence and raw shape before normalization or coercion. Missing/null/explicitly unavailable required evidence is UNKNOWN. Present wrong types, illegal enums, boolean-as-number inputs, nonfinite/impossible values, corrupt payloads and failed identity/digest checks are INTEGRITY_FAILURE. A structurally valid empty collection is distinct from a missing one. Optional branches require checked containing context: for example, a valid draft's explicit freeze state or a validated no-override declaration can exclude a dependent check, but missing applicability fields cannot. When a prerequisite is active, null never becomes AVAILABLE(None).
