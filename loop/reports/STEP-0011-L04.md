CLAIM L04-P10-M01: Pydantic v2's model_copy(update=...) does not validate the supplied update values before creating the copied model.

Source: [Pydantic BaseModel.model_copy](https://docs.pydantic.dev/2.12/api/base_model/#pydantic.main.BaseModel.model_copy). Retain constructor and repository revalidation, including copied nested values.

CLAIM L04-P10-M02: Pydantic 2.13.5's JsonValue union uses a discriminator with list, dict, string, boolean, integer, float and null variants, and has no tuple variant.

Source: [Pydantic v2.13.5 types.py](https://github.com/pydantic/pydantic/blob/v2.13.5/pydantic/types.py), `_get_type_name` and `JsonValue`; also inspected in the installed environment. Normalize JSON array representations locally at the new JSON-valued boundaries while retaining deep validation; do not change the shared L02 unpacking contract. Positive nested/empty-array tests must cover construction, repository admission, reopen and CLI input with explicit expected JSON values. This required L04 behavior does not authorize a repository-wide implementation of proposed item P0008-1.

CLAIM L04-P10-M03: SQLite permits one simultaneous write transaction, and BEGIN IMMEDIATE starts a write transaction immediately or can fail with SQLITE_BUSY when another writer is active.

Source: [SQLite transaction documentation, sections 2.1 and 2.2](https://www.sqlite.org/lang_transaction.html). Reuse the existing writer boundary for new state-dependent admission; separate repository writes do not establish whole-workflow atomicity.

CLAIM L04-P10-M04: SQLite trigger execution of RAISE(ABORT, message) terminates the triggering statement and returns SQLITE_CONSTRAINT with the supplied message.

Source: [SQLite CREATE TRIGGER, section 6](https://www.sqlite.org/lang_createtrigger.html). Reuse and test existing append-only guards; do not claim protection against database replacement or an administrator removing triggers.

CLAIM L04-P10-M05: Python 3.12's standard-library hashlib includes sha256 and supports hexadecimal hash output through hexdigest.

Source: [Python 3.12 hashlib documentation](https://docs.python.org/3.12/library/hashlib.html). Reuse artifact digests and media checksums; add no digest dependency or new hashing convention.

CLAIM L04-P10-M06: RFC 8785 sorts JSON object property names by UTF-16 code units and requires UTF-8 encoding of the resulting serialization.

Source: [RFC 8785 sections 3.2.3 and 3.2.4](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2.3). Consume L03 seals and their existing integer-only profile without changing canonicalization; ordinary artifact JSON and arbitrary generation settings are not claimed to be JCS.

CLAIM L04-P10-M07: A log limited to this CLI's access attempts and local seal, plan and registration events cannot establish that no earlier external viewing occurred or that media generation followed sealing.

This is a bounded inference from the observation surface, also required by L02/L04. Checkable counterexamples are viewing the source in another application before registration, or registering old media after recording a new seal and plan. No external witness or system-wide monitoring is included.
