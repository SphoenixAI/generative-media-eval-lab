### Rule interpretation and implementation approach

Add one bounded lint module with a versioned result contract and a pure graph checker, plus a read-only adapter for retained private data. Use exact kind/ID/revision identity and check supplied digest pins. Share the existing dataset/snapshot scope rather than scanning unrelated cases into the result. Preserve historical revisions in the audit and identify findings by revision; do not silently substitute a current record for an explicitly pinned predecessor. Follow references with a visited set, so cycles cannot hang traversal.

Inspect raw payloads before model construction for rules whose violations would otherwise be rejected or normalized away. In particular, constructor insertion of a residual must not hide W2, and frozen-plan validation must not prevent reporting E6. Tests may pass malformed TEST-ONLY payloads directly to this same checker and use isolated temporary database fixtures for adapter checks. Do not relax `Repository.put`, model validation, append-only triggers or the ordinary human-authoring APIs to make those fixtures admissible. Missing or corrupt graph context must remain visible even when other computable findings can still be returned.

The rule definitions below are implementation policies for the backlog, not inferred judgments about prose:

- **E1, error:** Check each terminal decision with intent for a warrant path to a MUST or SHOULD criterion in its exact pinned intent. A qualifying path uses an explicitly cited assessment with its human rationale and observation/evidence links, or a cited hypothesis/evidence relation path with the required human warrant and v2 creative anchor. It must stay within the decision's media and pinned intent context. Merely pointing to an intent, mentioning a criterion in prose, reaching a COULD/WONT criterion, or finding an unrelated anchored relation is insufficient. Report once per decision lacking a qualifying path. The checker verifies the structure and presence of warrants, not their persuasive correctness.
- **E2, error; E2w, warning:** Reuse the existing material-excuse predicate: a SATISFIED criterion assessment cites at least one MATERIAL, SEVERE or CATASTROPHIC observation. Read the exact assessment binding's provenance. RECONSTRUCTED and PROMPT_ONLY trigger E2; CONTEMPORANEOUS triggers E2w; SEALED does not trigger either. An expected-deviation declaration alone is not an actual excuse, and UNKNOWN observations are not treated as an ordered severity. Report once per qualifying assessment.
- **E3, error:** Compare evidence interval bounds, sampled timestamps and applicable attached-frame references against the matching retained decoded timeline. Preserve the repository's endpoint convention: interval ends may equal the timeline duration; sampled instants must identify a point before its end; frame indices must exist. Do not infer a timeline from nominal frame rate or the filename. Missing ingestion/timeline context is UNKNOWN, not zero duration or an in-bounds result. Report once per offending evidence revision even if several positions are invalid.
- **E4, error:** Check the relation predicate and both typed purpose fields against the existing vocabularies. The legacy `UNSPECIFIED` compatibility value belongs to W5, not E4; the v1 free-text `purpose` field is not a v2 vocabulary entry. Report once per invalid relation, naming all invalid fields.
- **E5, error:** Check a resolution's cited evidence against the exact hypotheses in its frozen plan, and an upward confidence revision against the preceding revision of that same claim. For confidence changes, include the declared new evidence and evidence actually cited by the revision; classify against the pre-revision claim context so changing a revision timestamp cannot turn new support into discovery. Fire only for a nonempty supporting basis whose required pair-role checks all compute DISCOVERY. Mixed SUPPORTING/TEST_RESULT evidence does not satisfy this rule. Empty evidence, missing prior confidence or unavailable role context is uncheckable, not an all-DISCOVERY result. Compare two present confidence values only; perform no arithmetic across claims. Emit one finding per offending resolution or confidence revision.
- **E6, error:** Recompute a frozen plan's digest from its retained raw payload with `test_plans.freeze_digest`, using the existing excluded-field contract. Report a mismatch or malformed/missing frozen digest once per frozen plan. Unfrozen drafts do not trigger E6. Do not canonicalize through a model that drops or supplies fields before this check.
- **E7, error:** Report a present decision override whose reason is absent, null, empty or whitespace-only. Absence of an override is not an error.
- **W1, warning:** Check explicitly typed motion claims, including a hypothesis linked to a motion TechnicalObservation by retained context. Fire when their nonempty cited support consists solely of still-image evidence or sampled/extracted frames, even if several different frames are cited. Interval/full-clip support prevents this warning; unknown coverage or an absent typed motion context remains uncheckable. Do not classify free text with keywords or author a motion claim.
- **W2, warning:** Report a raw exhaustive CompetingSet with no structural RESIDUAL member, before constructor normalization. Do not add the missing member during lint.
- **W3, warning:** Report a hypothesis with no distinct named alternative established by a matching `alternative_to` relation or membership with another named hypothesis in the same pinned CompetingSet context. A self-link, RESIDUAL, compatible_with or refines edge alone is not an alternative. Do not invent an alternative.
- **W4, warning:** Use the existing generation-linked arm condition for the sample-design requirement; do not infer stochasticity from descriptive prose. Report each such arm lacking either a valid count/stopping design or a nonblank decision rule. A non-generation arm does not acquire this requirement by default.
- **W5, warning:** Report once per relation with either typed purpose UNSPECIFIED, including a legacy compatibility view with both purposes unspecified. Preserve its original payload and digest.

Order findings by the fixed ruleset order, then subject kind, ID and revision; combine multiple invalid fields for the same rule and subject. Return completeness separately from the finding list so an empty list with missing context is never called a pass.

Add `lint` to the CLI's read-only dispatch before normal writable workspace construction. `ready` evaluates the same captured dataset revision and graph before appending its new operational-state revision. Recheck the input identity at that boundary and refuse stale inputs. A new typed lint-result artifact is included in `PilotSnapshot.records`, so the existing snapshot envelope need not gain defaults that would alter old digests. The artifact pins the audited records and is excluded from its own input graph to avoid a circular hash. Snapshot creation may retain complete diagnostic results containing lint errors; readiness is the operation blocked by those errors. Incomplete or corrupt record closure must still fail the existing snapshot integrity requirements. Snapshot export reads the saved result only, and lint data remains private.
