## Part 1. A2.1: five rules for the witness layer

These are structural. They are cheap now, because WP01 to WP05 do not exist yet, and expensive after they are built.

### Rule 1. Instrument authority is scoped

No witness has universal authority: not a human, a model, SAM, MediaPipe, optical flow, or the color instrument. An instrument result can support or contradict an observation only inside the scope where that instrument has been validated.

**WP02, add to the notes.**

ValidationRecord, append-only:
- instrument spec ref and digest;
- status: UNVALIDATED, PILOT or VALIDATED;
- validated_measurand;
- validated_domain (for example: 8-bit SDR, rgb24 decode, the codecs covered, a resolution range, a minimum region size in pixels);
- validated_conditions;
- known_blind_spots;
- calibration_evidence: test ids, fixture SHA-256s and the code version;
- authored_by and recorded_at.

An instrument's current status is derived from its latest ValidationRecord. A spec with no record is UNVALIDATED.

Who may write records:
- In tests, records exist only as TEST-ONLY fixtures.
- For real use, only Sphoenix writes VALIDATED records, with a CLI command such as `eval-pilot instrument validate`.
- The loop may write PILOT records whose evidence is synthetic tests only.

**WP02, append these acceptance strings.**
- "Instrument validity is derived from append-only ValidationRecords; a spec with no record is UNVALIDATED, and no record is ever edited in place."
- "A VALIDATED record without calibration evidence (test ids, fixture SHA-256s and code version) is rejected."
- "Every instrument run records whether its inputs fall inside the instrument's validated domain and conditions, with the reason when they do not."

**WP03, add to the notes.**

A new check result: MEASURED_UNVALIDATED. The instrument produced a value, but it is not VALIDATED, or this input is outside its validated domain or conditions. The value is kept and shown. It never supports or contradicts anything.

Now:
- SUPPORTED and CONTRADICTED require a VALIDATED instrument, used inside its validated scope.
- UNMEASURABLE still means no value could be produced.
- Post-reveal changes whose only checks are MEASURED_UNVALIDATED are classed UNRESOLVED.

**WP03, append these acceptance strings.**
- "A check by an UNVALIDATED or PILOT instrument, or by a VALIDATED instrument outside its validated domain or conditions, yields MEASURED_UNVALIDATED and never SUPPORTED or CONTRADICTED; each case has a test."
- "MEASURED_UNVALIDATED keeps the measured value in the check record and in the witness report."

**WP04, append this acceptance string.**
- "A dose measured by an instrument that is not VALIDATED for that clip's domain is recorded as UNVERIFIED_DOSE, and such canaries are excluded from detection thresholds."

**WP05, append this acceptance string.**
- "PERCEPTION and THRESHOLD require VALIDATED, in-scope checks; with only MEASURED_UNVALIDATED evidence the dispute is INSUFFICIENT."

### Rule 2. Witness exposure is recorded by channel

One BLIND or NOT_BLIND flag throws away which evidence a judge had seen. Record exposure by channel. The current workflow still uses only the intent reveal.

**WP01, add to the notes.**

Exposure channels:
- PIXELS
- AUDIO
- PROMPT
- INTENT
- MODEL_IDENTITY
- OTHER_JUDGE_STATEMENT
- INSTRUMENT_RESULT

ExposureEvent, append-only: judge_ref; channel; target ref; source (CLI_LOGGED or DECLARED); at. It replaces A2's IntentViewEvent, which becomes the ExposureEvent for channel INTENT.

A judge may declare an exposure the CLI could not see, for example "I read the prompt elsewhere". Declarations can only add exposure, never remove it.

Each BlindStatement stores the exposure set at sealing time, derived from the events. Blindness is derived per channel. A2's BLIND and NOT_BLIND now mean blindness on the INTENT channel, and every A2 rule that names them keeps that meaning.

A RevealEvent names one channel. The CLI implements only the INTENT reveal for now. Revealing any other channel is rejected with a message saying it is deferred to proposal A3-01.

**WP01, append these acceptance strings.**
- "Each sealed blind statement stores the set of exposed channels at sealing time, derived from append-only ExposureEvents; tests cover CLI-logged and declared exposures."
- "A declared exposure can only add to the exposure set; nothing removes an exposure."
- "Blindness is derived per channel, and A2's BLIND and NOT_BLIND refer to the INTENT channel."
- "A reveal of any channel other than INTENT is rejected with a message naming proposal A3-01."

### Rule 3. Evidence lineage is explicit

Outputs that come from the same upstream source are one witness, however many conclusions use them. The repository already says this about specialist agents: shared model errors mean thirteen specialist names are not thirteen independent votes.

**WP02, add to the notes.**

Every InstrumentRun records its upstream inputs:
- the clip;
- any mask or label file, as an imported-artifact ref with its SHA-256 and producing tool;
- any earlier run whose outputs it consumed.

Its evidence roots are the set of clip, import and root-run refs it descends from.

**WP03, add to the notes.**

Every ClaimCheck carries the evidence roots of its run. When several checks bear on one claim, the report groups them into dependency families: checks whose roots overlap form one family. Corroboration is counted in families, not checks. Witness cards count families.

**WP03, append this acceptance string.**
- "Two checks whose runs share an evidence root count as one dependency family, and corroboration counts in reports and witness cards are family counts; a test uses two checks derived from one mask file."

### Rule 4. Human reveal order stays fixed

A person who has seen the prompt can never again give a prompt-blind statement on that clip. Humans therefore use fixed protocols. Arbitrary evidence partitions are deferred, and are mainly for fresh-context model witnesses (A3-01).

**WP01, add to the notes.**

`protocol_version` names a fixed protocol. Only one human protocol exists now:

HUMAN_MEDIA_FIRST_V1:
1. PIXELS and AUDIO only;
2. seal the blind statement;
3. reveal INTENT;
4. log post-reveal changes;
5. write assessments.

A later cohort protocol, such as media plus prompt before sealing, needs Sphoenix's approval.

**WP01, append this acceptance string.**
- "A HUMAN session must use a named fixed protocol; a second session by the same judge on the same clip derives blindness from that judge's full exposure history, so it is NOT_BLIND on every channel the judge has already seen."

### Rule 5. Automated is not the same as true

An instrument measurement is evidence whose authority depends on validation. It is never ground truth because a machine produced it.
- CONTRADICTED means a VALIDATED, in-scope measurement disagrees with the observation.
- The observation stays stored, unchanged, and is never marked false.

**WP03, append this acceptance string.**
- "No check, class or report edits, hides or marks false any witness observation; CONTRADICTED is recorded beside the observation."

**WP08, append these acceptance strings.**
- "The document states that instrument authority is scoped by validation and that measurement is evidence, not ground truth."
- "Conceptual examples that the lab cannot yet measure, such as a subject that appears to slide, are labelled as hypothesis examples and claim no measured result."
